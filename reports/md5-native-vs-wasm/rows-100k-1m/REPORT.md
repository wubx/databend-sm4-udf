# 内置 MD5 与 WASM MD5：10–100 万行

**状态：完整测量已结束，结果一致且清理成功。** 此轮只测两种 MD5，不含 identity 和 SM4。小规模结果见 [1–5 万行报告](../rows-1-50k/REPORT.md)，两轮独立测量；其他报告见 [报告索引](../../README.md)。

## 1. 测试目标与环境

检验扩大行数后，WASM 的固定加载/初始化成本是否被摊薄，以及完整 SQL 的相对差距如何变化。

| 项目 | 值 |
| --- | --- |
| Databend | Databend Query v1.2.947-nightly-f3733a6b32(rust-1.100.0-nightly-2026-09-21T02:16:50.512714833Z) |
| CPU | AMD Ryzen 9 5950X 16-Core Processor |
| 宿主逻辑 CPU | 32 |
| Query max_threads | 1 |
| max_block_size | 8192 |
| 表引擎 | Memory |
| 结果缓存 | 关闭 |
| 实现 | 内置 md5() / WASM MD5，STRING → 小写 Hex STRING |
| MD5 库 | md-5 0.10.6；原生版本依据本地源码/锁文件，未重编译 Query 控制全部变量 |
| Rust | rustc 1.97.1 (8bab26f4f 2026-07-14) |
| 开始 UTC | 2026-10-19T09:46:53.746643+00:00 |
| 结束 UTC | 2026-10-19T09:48:02.044186+00:00 |

- 明文字节数 `[16, 128, 1024]`；行数 `[100000, 300000, 1000000]`；每组预热 1 次、正式 5 次，正式顺序交错打乱。
- 输入在 Memory 表中预生成，固定宽度行号使每行不同，文本使用重复/截断的 Hello Databend 模式。
- 生成、写表、上传、注册不计时。每次 SQL 的初始化/编译、列式数据扫描、转换、MD5 和 hash 聚合全部计时。
- `count(*)` 与 `sum(siphash64(result))` 消费返回值，且每次全量 count/checksum 与原生预计算结果一致。
- 27 个 NULL/空串/标准向量/UTF-8/零字节/边界用例，独立期望来自 Python hashlib；每种长度额外逐行核对 257 行。
- 共 108 次计时查询，没有 identity 测量。固定工件仍含旧 identity 导出，但本轮未注册或调用它。

## 5. 规模增量观察

以下取 100,000 → 1,000,000 行的中位数差，再除以增加的行数，单位为每增加一行的平均增量微秒。

| 输入 B/行 | 内置增量 µs/行 | WASM 增量 µs/行 | WASM/内置增量比 |
| --- | --- | --- | --- |
| 16 | 0.137 | 0.331 | 2.42× |
| 128 | 0.302 | 0.678 | 2.24× |
| 1024 | 1.467 | 3.570 | 2.43× |

耗时比随规模下降，与固定成本占比下降一致；剩余差距还包含 native/WASM target 的编译差异、结果 buffer/String 分配和执行边界。

## 6. 复现

从项目根目录构建后，在有管理员批准的独立测试实例运行：

```bash
export SM4_URL=http://127.0.0.1:8000
export SM4_USER=root
export SM4_PASSWORD=''
.venv/bin/python benchmarks/native-vs-wasm/benchmark.py --md5-only \
  --rows 100000,300000,1000000 --lengths 16,128,1024 --repeats 5 \
  --output results/native-vs-wasm-large.json \
  --report-dir reports/md5-native-vs-wasm/rows-100k-1m
```

WASM 工件构建方法见 [实验说明](../../../benchmarks/native-vs-wasm/README.md)；自定义 CARGO_TARGET_DIR 时传 --wasm-file。1,024 B × 100 万行仅原文就约 0.95 GiB，应预留输入表、运行时和中间结果的内存。不要未经批准在生产运行。

用完整原始记录重新生成本页，不覆盖上一轮：

```bash
.venv/bin/python benchmarks/native-vs-wasm/report.py \
  --input results/native-vs-wasm-large.json \
  --report-dir reports/md5-native-vs-wasm/rows-100k-1m
```

- 未测并发 QPS、峰值 RSS、多线程扩展、冷进程启动或纯内核计算。单机共享环境、无绑核。
- 未尝试模块缓存等运行时优化。
- 没有修改已部署 SM4；临时函数、表、stage 正常退出时清理。
- WASM SHA256：`0d90342bf4926265357099ddf0762b78b0df5025f83eea0080552bd9bebac552`。完整脱敏证据与工件/源码指纹见 [results.json](results.json)。
