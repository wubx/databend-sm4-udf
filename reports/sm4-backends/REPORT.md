## 3. 三方性能

- 固定 `explicit_iv`，CBC **解密**；三端都用 `(BINARY, STRING, STRING, STRING) -> BINARY`。
- 16/128/1,024 B × 1,000/10,000/30,000/50,000 行，共 12 个规模；每种实现预热一次、正式 3 次，顺序确定性打乱。
- 明文按 `Hello Databend` 模式重复/截断，带固定宽度行号保证各行不同；16 B 时文字会被截断。
- 密文预生成、写表和 Python 进程启动不计时；每行仍执行相同的 key/IV 处理，无密钥缓存。
- 结果按 count/hash 聚合消费，每次与明文基线校验；不返回大量明文，避免客户端渲染主导。
- 时间是完整服务端 SQL 耗时，含扫描/hash、运行时创建/编译、Arrow 转换及 Python RPC。

## 5. 复现

先按 [README](../../README.md) 安装依赖、构建 WASM，在有权限的专用实例配置 UDF 访问策略：

```bash
make test
make wasm
export SM4_URL=http://127.0.0.1:8000
export SM4_USER=root
export SM4_PASSWORD=''
.venv/bin/python scripts/integration.py --benchmark-smoke --benchmark-report \
  --benchmark-report-rows 1000,10000,30000,50000
```

此命令创建随机前缀的临时函数和表，完成后自动清理，不更改实例安全设置。如果只跑性能且已注册公开函数、Python Server 也已启动：

```bash
.venv/bin/python scripts/benchmark.py --profile explicit_iv \
  --lengths 16,128,1024 --rows 1000,10000,30000,50000 --modes CBC \
  --operations decrypt --repeats 3
```

原始 `results/` 仍被 Git 忽略。`scripts/report_results.py` 接受完整本地记录，校验完成标志、重复次数、checksum 和源码指纹，输出本报告及脱敏摘要。

## 6. 边界与安全

- 未测：压力并发、峰值 RSS、跨机网络、TLS、高可用。
- 兼容性范围见 [参数约定](../../docs/COMPATIBILITY.md) 和固定参考向量。
- 默认 IV 是固定兼容值，不适合作为生产 IV 策略；示例密钥公开，不用于真实数据。
- ECB/CBC/CFB128/OFB 不提供认证；解密非 NULL 不证明数据未篡改或密钥正确。
- 实现未保证常数时间，未经密码学安全审计；详见 [SECURITY](../../SECURITY.md)。
- 修改实现后需重新测量。
